---

## 1. The Anatomy of an Alibaba MTOP Request

Alibaba web and mobile clients communicate through the unified Mobile TOP gateway (`acs.m.taobao.com` or `h5api.m.goofish.com`).

Every request to an endpoint (such as `mtop.idle.web.user.page.head` for seller profiles or `mtop.idle.web.trade.rate.list` for buyer reviews) requires specific URL query parameters:

```text
jsv: 2.7.2
appKey: 34839810
t: 1712491200000          (13-digit Unix timestamp in ms)
sign: 8a4b6c...            (32-character hexadecimal MD5 hash)
api: mtop.idle.web.user.page.head
v: 1.0
type: originaljson
dataType: json
data: {"userId":"2216555697343","self":false}
```

If the `sign` parameter does not match the exact cryptographic digest calculated on Alibaba's gateway servers, you get an immediate error:
`FAIL_SYS_ILLEGAL_ACCESS` or `FAIL_SYS_TOKEN_EXOIRED`.

---

## 2. The MTOP Token Bootstrap Handshake

Where does the cryptographic secret come from?

When a client first visits an Alibaba domain, the server sets a cookie named `_m_h5_tk`. Its structure looks like this:

```text
_m_h5_tk = "a1b2c3d4e5f67890abcdef1234567890_1712494800000"
_m_h5_tk_enc = "..."
```

Notice the underscore (`_`):
- The prefix before the underscore (`a1b2c3d4e5f67890abcdef1234567890`) is the **Token Secret**.
- The suffix after the underscore is the expiration timestamp.

If you don't have this cookie, an unauthenticated request to any MTOP endpoint will return `FAIL_SYS_TOKEN_EXOIRED`, but the response headers will supply a fresh `_m_h5_tk` cookie in `Set-Cookie`.

---

## 3. The Cryptographic Signing Algorithm

Once you have the `token` from `_m_h5_tk`, the signature is calculated by concatenating four values delimited by `&` and taking the MD5 digest:

$$\text{SignString} = \text{Token} + \text{"\&"} + \text{Timestamp} + \text{"\&"} + \text{AppKey} + \text{"\&"} + \text{DataJSON}$$

```python
import hashlib
import time
import json

def generate_mtop_sign(token: str, app_key: str, data_json: str, timestamp_ms: int) -> str:
    # 1. Take the token prefix before '_'
    token_secret = token.split('_')[0]
    
    # 2. Build the signing string
    sign_str = f"{token_secret}&{timestamp_ms}&{app_key}&{data_json}"
    
    # 3. Compute hexadecimal MD5 digest
    return hashlib.md5(sign_str.encode('utf-8')).hexdigest()
```

### The Pitfalls That Trip Everyone Up:
1. **JSON Whitespace:** `data_json` must have **zero whitespace between keys and colons** (`json.dumps(data, separators=(',', ':'))`). Any rogue space results in `FAIL_SYS_ILLEGAL_ACCESS`.
2. **Clock Skew:** Alibaba servers reject signatures if `t` drifts by more than ~15 seconds from network time.
3. **AppKey Mismatch:** Different MTOP endpoints use different AppKeys. For Goofish web endpoints, `34839810` or `12574478` are standard.

---

## 4. Bypassing TLS & JA3/JA4 Fingerprinting

Even if your signature is mathematically perfect, running Python’s standard `requests` or `aiohttp` against `acs.m.taobao.com` will immediately get you blocked or dropped by Alibaba’s CDN (Baxia / Sec-Guard WAF).

Why? Standard Python HTTP libraries negotiate TLS with standard OpenSSL ciphers that broadcast obvious scraper signatures.

To solve this completely over pure HTTP:
Use **`curl_cffi`** with modern browser TLS impersonation:

```python
from curl_cffi import requests

session = requests.Session(impersonate="chrome124")

headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36",
    "Referer": "https://www.goofish.com/",
    "Origin": "https://www.goofish.com",
}

response = session.get(
    "https://acs.m.taobao.com/gw/mtop.idle.web.user.page.head/1.0/",
    params=params,
    headers=headers,
    timeout=15.0
)
```

By matching Chrome 124’s exact TLS extensions, elliptic curves, HTTP/2 SETTINGS frames, and pseudo-header ordering, the MTOP gateway treats the pure HTTP request identically to a native browser tab.

Sellers can easily steal studio photos or official prototype images for their listings.

- Did buyers complain about counterfeit items (假货)?

- Did the seller refuse returns on defective items?

### 4. Sales Velocity: Active Listings vs. Sold History
Check the seller's completed sales:
- How many items have they successfully sold?
- Are they an actual collector offloading their personal collection (diverse items, reasonable prices)?
